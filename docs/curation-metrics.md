# Analysis 탭 지표 정의 — 큐레이션 후보 목록의 칼럼들

`apps/collect_workspace.py` Analysis 탭 · 계산은 전부 `mstack/episode_stats.py`

지표는 셋뿐입니다: **평균과 차이 · 멈춤% · 길이.**

---

## 1. 칼럼 정의

측정값은 실기 258개 에피소드(9 task, 42,169프레임, 20Hz) 기준입니다.
계산은 **팔 7관절만** 씁니다 — 그리퍼는 0/1 이산값이라 열릴 때마다 `|Δa|=1`이 되어서
섞으면 모든 에피소드가 똑같이 거칠어 보입니다.

| 칼럼 | 정의 | 단위 | 실측 (p50 / max) |
|---|---|---|---|
| **에피소드** | `파일명 · demo_N` | — | — |
| **평균과 차이** | 이 에피소드의 평균 `\|Δa\|` **−** 같은 task 에피소드들의 평균 | rad/frame | \|편차\| **0.0008** / 0.0037 |
| **멈춤%** | `max(7관절 \|Δa\|) < 0.002` 인 프레임 비율 | % | **12** / 28 |
| **길이** | 프레임수 ÷ 20 | 초 | **8.2** / 12.2 |
| **task** | language instruction | — | — |

`Δa` = 연속 두 프레임의 관절각 차이 = **속도**. 20Hz라 프레임 간격 50ms.

**평균과 차이**는 부호가 있습니다:
- `+0.0036` = 같은 작업의 보통 테이크보다 **급하게** 움직임 → 빨강
- `-0.0037` = 보통 테이크보다 **느리게/늘어지게** 움직임 → 파랑
- `+0.0002` = 평범

> 화면에서 각 칼럼 **헤더에 마우스를 올리면** 같은 정의가 툴팁으로 뜹니다.
> 목록 위 `?` 버튼을 누르면 이 문서가 그대로 열립니다.

## 2. 판정선 — `mstack/episode_stats.py` 상단 2줄이 전부

```python
TASK_DEV_LIMIT = 0.0026   # 같은 task 평균과 이만큼 벗어나면 표시. 258개 중 19개
STILL_VEL      = 0.002    # 이 속도 미만이면 "멈춰 있음" (≈2.3°/s, 손만 얹은 상태)
```

숫자를 조이거나 풀려면 이 두 줄만 고치면 됩니다. 화면 문구·툴팁·`[튀는 것만 선택]`
버튼이 전부 여기서 읽어가므로 표시값과 판정값이 갈라지지 않습니다.

## 3. 왜 task **안에서** 비교하나

`평균 |Δa|`는 근사가 아니라 **항등식**입니다:

```
평균|Δa| ≡ 총이동거리 / ((T-1) × 7)      # 검증: 0.00660089 = 0.00660089
```

즉 **평균 속도 = 거리 ÷ 시간**. 그래서 task끼리 비교하면 조작 품질이 아니라
**팔이 얼마나 멀리 뻗어야 하는 작업인가**를 재게 됩니다:

```
corr(평균속도, 이동거리) = +0.89
corr(평균속도, 프레임수) = +0.23
green bowl 13.99 rad  ↔  white cup→yellow bowl 7.14 rad   (96% 차이)
```

전체를 한 줄로 세워 자르면 실제로 이렇게 됩니다:

```
절대 기준 0.0095로 컷 →  green bowl 19/22(86%) 삭제,  white cup→white bowl 0/33
```

**같은 task 안에서는** 거리가 거의 고정되므로, 평균과의 차이가 곧 "이 테이크만 유난히
급했다/늘어졌다"가 됩니다. 그래서 비교는 task 안에서, 표시는 차이(rad/frame)로 합니다.

알려진 한계: task마다 중심뿐 아니라 **퍼짐도** 다릅니다(각자 평균의 10%~27%). 그래서
`±0.0026` 하나로 자르면 퍼짐이 큰 task에서 비례적으로 더 많이 걸립니다. 표시된 것은
**"확인해봐라"**이지 **"지워라"**가 아닙니다.

## 4. 수집할 때의 행동 대응

| 화면에 보이는 것 | 실제로 무슨 일이 있었나 | 다음 수집에서 |
|---|---|---|
| 차이가 크게 **+** | 그 작업치고 급하게 몰아붙임 | 손을 얹고 안정된 뒤 녹화 시작, 한 번의 연속 동작으로 |
| 차이가 크게 **−** | 늘어졌거나 중간에 헤맴 | 놓을 자리를 미리 정하고 시작 |
| 멈춤% 25% 이상 | "어디 놓지?" 하고 멈춤 | 위와 같음 |
| 길이 5초 미만 | 중단됐거나 실수 저장 | — |
| 길이가 유난히 긺 | 목표를 지나쳐 되돌아옴 | 한 번에 가져가기 |

## 5. 버린 방식들 — 되돌리지 말 것

| 버린 것 | 왜 |
|---|---|
| **task 내 z-score** (`z ≥ 2`) | task별로 가장 고르게 잡았지만 `z = +2.3`을 보고 조작자가 할 수 있는 판단이 없음 |
| **task 중앙값 대비 배율** (`x1.35`) | 읽히긴 하나 값이 비율이라 다른 칼럼과 단위가 갈림 |
| **가속 p95 / 스파이크** | task 무관성은 가장 좋았지만(0.47/0.44) 현장에서 쓸 지표로 채택 안 함 |
| **평균\|Δa\| 절대 기준** | 위 3항. 한 task를 통째로 삭제 |
| **팔로워 속도 한계(0.05 rad/tick) 초과 검출** | `actions`는 리더의 명령이고 팔로워를 앞서는 게 정상 → 99%가 걸림. 규약의 성질이지 결함이 아님 |

## 6. 삭제 절차

```
1) Statistics 패널 → [다시 분석]
2) 요약 문장 확인:  "자기 task 평균에서 0.0026 넘게 벗어난 것 N개 (급함 a / 늘어짐 b)"
       N = 0 이면 잘라낼 것 없음. 끝.
3) 정렬 = "평균과 차이 큰 순" (급한 쪽) → 다시 "작은 순" (느린 쪽)
4) 위에서부터 클릭 → 왼쪽 곡선(state 실선 / commanded 파선 / action 점선) 확인
5) [재생해서 확인] 으로 영상까지 본 뒤에만 [선택 삭제]
```

숫자는 "이거 재생해봐라"까지가 역할입니다. 자동 삭제 경로는 없고, 목록에서 고른 것만
지웁니다. `[튀는 것만 선택]` 버튼도 Dataset 트리에 **선택만** 하고 삭제하지 않습니다.
